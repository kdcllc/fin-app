Goal ledger-core (phase A of replacing GnuCash with fin-app) — outcome: shipped on branch feature/ledger-core (PR pending).

Delivered: migration 0009 rebuilds the book as a double-entry ledger (accounts tree with GnuCash-compatible types, transactions, splits that are debit-positive integer cents summing to 0, legacy_category_map); every legacy payment became a two-split transaction with identical id/date/amount/memo/provenance; categories became EXPENSE accounts. A TypeScript ledger domain API (post/update/delete, balances, register running balance, transfer, income, opening balance) sits under facades that keep the old payments/categories/accounts/payees repository contracts, so reports, bills grid, dashboard and importers kept working. New Accounts and Register pages. GnuCash QIF/CSV export and reconcile-vs-GnuCash were retired.

Key decisions: ledger + payment facade (reports read only "payment-shaped" transactions = payee + exactly one EXPENSE split + one ASSET/LIABILITY split); xlsx dedup identity uses snapshot columns (import_account_id / import_amount_cents) so edits do not break re-import detection; re-imports of transactions edited out of payment shape are exact_duplicate (xlsx) / unchanged (GnuCash) — local edits win; migration runner runs with foreign keys OFF and gates on PRAGMA foreign_key_check (mirrored in tests/support/test-db.ts).

Remember next time: (1) fix cycles were mostly about unstated semantics (null vs undefined on patch, re-import of edited rows) — state them in the task file up front. (2) The QA gate found two pre-existing UI bugs that unit tests hid (GnuCash import tree always empty; xlsx report exports fail on a serde field-name mismatch, backlog B81). (3) Follow-on goals B–F: full GnuCash import (SQLite + compressed XML), shared book with lock file, reconciliation (must close the reconcile-lock bypasses B41/B67), statement import, budgets. Backlog lives in the goal's follow-ups.md (B1–B86).
